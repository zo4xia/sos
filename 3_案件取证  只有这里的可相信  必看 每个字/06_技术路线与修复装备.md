# 技术路线与修复装备

## 甲方偏好

甲方允许并偏好使用成熟模板框架快速建设前端和后端，理由是标准框架和组件比大量手写实现更不容易出错。

## 路线原则

1. 业务先于模板：模板只负责工程骨架、组件和通用交互，不能决定业务语义。
2. 单一主线：不能把两个未理解的版本按文件随意拼接。
3. 标准优先：优先采用项目现有框架、成熟组件和官方文档中的稳定用法。
4. 业务验收：每个生成或重组的页面必须回指甲方事实，尤其是归属地、D 日、审核截止日期、参选人和权限。
5. 最小重建：只有在证据证明原实现已污染且无法修复时，才考虑使用模板重建模块。

## TDesign MCP

工具名：`tdesign-mcp-server`

来源：腾讯官方 TDesign MCP，甲方提供配置示例。

配置示例：

```json
{
  "mcpServers": {
    "tdesign-mcp-server": {
      "command": "npx",
      "args": ["-y", "tdesign-mcp-server@latest"]
    }
  }
}
```

## 适合使用的任务

- 后台管理端标准表格、筛选、详情抽屉、审核弹窗、表单和权限可见性。
- 候选人详情与附件预览的标准化交互。
- 归属地、角色、阶段和审核状态的管理端展示。
- 统一按钮、表格、通知、日期窗口提示和错误反馈。

## 禁止越权的任务

- 不生成选民、投票人或 C 端投票管理模块。
- 不自行定义候选人和选民的同义关系。
- 不让模板默认开放注册、跨归属地查看或跨组织操作。
- 不用组件生成结果替代线下评审事实。
- 不以页面完成或组件渲染成功宣称业务完成。

## 使用前检查

- [ ] 当前 MCP 配置是否确实加入了该 server。
- [ ] server 是否能连接，工具真实名称和参数 schema 是什么。
- [ ] 当前前端技术栈和 TDesign 版本是否兼容。
- [ ] 生成内容是否落在独立分支或可回滚工作区。
- [ ] 生成页面是否有对应甲方证据编号和验收用例。
