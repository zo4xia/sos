🏛️ 封地一：归属地与权限 领主：platform_admin
管辖表（7）
organizations users memberships roles role_permissions sessions invitations
商贸出参（供应什么）
→ organization_id 给所有业务表做归属地隔离
→ user_id + role 给所有操作做鉴权
→ session token 给API请求做认证
商贸入参（需要什么）
← 超管创建归属地、开账号、分配角色
← 小程序用户注册（自动创建user+candidate membership）
关键字段流转
memberships.role → 后端roleGuard鉴权 → 前端菜单过滤
organizations.org_type → pipeline选村/社区模板
users.phone → 登录账号（全局唯一，绑死归属地）
🗳️ 封地二：选举活动 领主：sub_admin + editor
管辖表（6）
election_proposals election_fiefs election_fief_stages stage_templates election_terms election_units
商贸出参（供应什么）
→ election_fief_id 给岗位/候选人/材料/公告做活动关联
→ d_day 给pipeline倒排所有日期
→ stages 给活动详情页时间轴 + 公告阶段关联
→ positions 给候选人报名 + 审核日期
商贸入参（需要什么）
← editor提交提案(name/d_day/positions/jsonb)
← reviewer审核提案(approved/rejected)
← stage_templates提供倒排规则（村/社区两套）
关键字段流转
proposals.d_day → pipeline → stages.start/end_date
proposals.positions(jsonb) → pipeline → positions表
proposals.status=approved → 触发pipeline生成fief+stages+positions+announcements
stages.stage_key → announcements.stage_key 关联
👥 封地三：岗位与候选人 领主：reviewer + candidate
管辖表（5）
positions candidates candidate_reviews materials material_files
商贸出参（供应什么）
→ candidates列表给候选人管理页
→ candidate_reviews给审核历史追溯 + 小程序结果展示
→ materials+material_files给审核弹窗附件预览
→ positions.application_end/material_review_end给审核截止日期
商贸入参（需要什么）
← candidate小程序提交材料(title/description/files)
← reviewer审核(decision=approved/rejected, note=驳回意见)
← positions由pipeline从提案生成（不手动建）
关键字段流转
materials.id → candidates.material_id
material_files.material_id → 材料附件列表（多个！）
candidates.current_round → preliminary/joint/inspection
candidate_reviews.round+decision+note → 小程序个人中心展示
positions.material_review_end → 审核截止日期标记
📢 封地四：公告 领主：editor
管辖表（2）
announcements announcement_templates
商贸出参（供应什么）
→ published公告给小程序前端展示
→ draft公告给小编工作台编辑
→ 公告附件(business_files)给小程序下载
商贸入参（需要什么）
← pipeline根据stage_key+template_id自动生成draft
← editor编辑(title/body/落款/成文日期)
← editor发布(status=published, published_by/at)
← announcement_templates提供18套甲方模板原文
关键字段流转
templates.at_content(含占位符) → pipeline填充 → announcements.body
announcements.stage_key → stages.stage_key 关联阶段
announcements.status=draft/published → 小编工作台状态
business_files(ref_type=announcement) → 公告附件
📎 封地五：附件与通知 领主：sub_admin
管辖表（2）
business_files webhook_subscriptions
商贸出参（供应什么）
→ /files/:key 匿名下载接口（32hex不可猜）
→ webhook推送给企业微信/飞书群
→ 通用附件给公告/岗位/提案复用
商贸入参（需要什么）
← 所有模块上传文件(/files/upload → storage_key)
← sub_admin配置webhook(channel/url/mobile)
← 定时任务触发提醒(到点推送)
关键字段流转
business_files.ref_type+ref_id → polymorphic关联
storage_key → /files/:key 下载路径
webhook_subscriptions.url → 推送目标
uploads目录按归属地/届/来源类型归档
封地治理原则：每个封地有唯一职责，不重复造轮子。商贸线路清晰：出参=供应什么，入参=需要什么。
字段不悬空：每个字段都落在某个封地手上，在商贸线路上有明确的生产→消费路径。找不到消费者的字段=待清理或待实现。
填空题：每个封地领主要回答——我管辖的字段，在前端哪个页面用？在后端哪个接口读写？在商贸线路上从哪来、到哪去？
